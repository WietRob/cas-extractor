## Primary Flag: `--enable-h29-resolution-metadata`

### Purpose

Enable/disable resolution metadata for self.attr.method() calls.

### Values

| Value | Behavior |
|-------|----------|
| `false` (default) | H2.9 disabled, no metadata added |
| `true` | H2.9 enabled, resolution metadata added to CallEntry |

### CLI Usage

```bash
# Enable H2.9 metadata
python3 extract_python.py \
  --enable-h29-resolution-metadata true \
  --repo-root . \
  --repo-name repo://main \
  --revision git:HEAD \
  --out ./evidence

# Disable H2.9 (explicit)
python3 extract_python.py \
  --enable-h29-resolution-metadata false \
  --repo-root . \
  --out ./evidence
```

### ENV Usage

```bash
CAS_ENABLE_H29_RESOLUTION_METADATA=true python3 extract_python.py ...
```

### Help Text

```
  --enable-h29-resolution-metadata ENABLE_H29_RESOLUTION_METADATA
                        Enable H2.9: add resolution metadata to self.attr.method()
                        calls showing which heuristic resolved the call and source location.
                        (default: false, ENV: CAS_ENABLE_H29_RESOLUTION_METADATA)
```

## Interaction with Existing Flags

H2.9 adds metadata on TOP of existing H1-H3 resolution - no interaction.

| H2.5 | H2.6 | H2.7 | H2.8 | H2.9 Metadata |
|------|------|------|------|---------------|
| OFF | OFF | OFF | OFF | Works (shows H2/H1/H3) |
| ON | OFF | OFF | OFF | Works |
| ON | ON | ON | ON | Works |

---

## Default Behavior Rationale

### Why H2.9 Default is `false`

1. **Opt-in**: Metadata is useful for debugging/analysis, not for production
2. **Backward Compatible**: No behavior change, but adds field to output
3. **Schema Change**: CallEntry gets new optional field
