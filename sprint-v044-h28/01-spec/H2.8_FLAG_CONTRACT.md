# H2.8 Flag Contract — Feature Flag Design

**Feature-ID:** H2.8
**Sprint:** v0.4.4
**Status:** Contract Definition

## Flag Overview

| Flag | Type | Default | ENV Variable |
|------|------|---------|--------------|
| `--enable-h28-factory-return` | bool | `false` | `CAS_ENABLE_H28_FACTORY_RETURN` |
| `--h28-max-factory-depth` | int | `1` | `CAS_H28_MAX_FACTORY_DEPTH` |

---

## Primary Flag: `--enable-h28-factory-return`

### Purpose

Enable/disable H2.8 factory return inference for call resolution.

### Values

| Value | Behavior |
|-------|----------|
| `false` (default) | H2.8 disabled, factories return unknown types |
| `true` | H2.8 enabled, direct factory returns inferred |

### CLI Usage

```bash
# Enable H2.8
python3 extract_python.py \
  --enable-h28-factory-return true \
  --repo-root . \
  --repo-name repo://main \
  --revision git:HEAD \
  --out ./evidence

# Disable H2.8 (explicit)
python3 extract_python.py \
  --enable-h28-factory-return false \
  --repo-root . \
  --out ./evidence
```

### ENV Usage

```bash
CAS_ENABLE_H28_FACTORY_RETURN=true python3 extract_python.py ...
```

### Precedence

```
CLI flag > ENV variable > Default (false)
```

### Help Text

```
  --enable-h28-factory-return ENABLE_H28_FACTORY_RETURN
                        Enable H2.8: infer return types from factory functions
                        that directly return ClassName(). Used for resolving
                        calls like x = factory(); x.method() where factory()
                        returns a known class instance.
                        (default: false, ENV: CAS_ENABLE_H28_FACTORY_RETURN)
```

---

## Secondary Flag: `--h28-max-factory-depth`

### Purpose

Control maximum factory chain depth for H2.8 inference.

### Values

| Value | Behavior |
|-------|----------|
| `0` | H2.8 effectively disabled (no inference) |
| `1` (default) | Direct factory return only |
| `2+` | Reserved for future multi-hop factory chains |

### CLI Usage

```bash
# Depth 1 (default, conservative)
python3 extract_python.py \
  --enable-h28-factory-return true \
  --h28-max-factory-depth 1 \
  --repo-root . \
  --out ./evidence
```

### Help Text

```
  --h28-max-factory-depth H28_MAX_FACTORY_DEPTH
                        Maximum factory chain depth for H2.8 inference.
                        Depth 1 = direct factory return only.
                        Only effective when --enable-h28-factory-return is true.
                        (default: 1, ENV: CAS_H28_MAX_FACTORY_DEPTH)
```

## Interaction with Existing Flags

### H2.5, H2.6, H2.7 and H2.8 Flags

| H2.5 | H2.6 | H2.7 | H2.8 | Resolution Order |
|------|------|------|------|------------------|
| OFF | OFF | OFF | OFF | H1 > H2 > H3 |
| OFF | OFF | OFF | ON | H1+H2.8 > H2 > H3 |
| ON | OFF | OFF | ON | H2.5 > H2.8 > H2 > H1 |
| ON | ON | OFF | ON | H2.5 > H2.6 > H2.8 > H2 |
| ON | ON | ON | ON | H2.5 > H2.7 > H2.6 > H2.8 > H2 |

### Resolution Priority (All Flags ON)

1. **H2.5 method-local** (intra-method assignment)
2. **H2.7 transitive propagated** (multi-hop helper chain)
3. **H2.6 single-hop propagated** (direct helper)
4. **H2.8 factory-inferred** (factory return type)
5. **H2 class-level** (`__init__` assignment)
6. **H1 local-var** (local var constructor)

---

## Default Behavior Rationale

### Why H2.8 Default is `false`

1. **Safety First:** Factory inference adds complexity with potential for incorrect types
2. **Backward Compatibility:** v0.4.4 produces identical results to v0.4.3 by default
3. **Explicit Opt-In:** Users consciously enable factory inference
4. **Audit-Friendly:** Conservative defaults reduce audit noise

### Why Depth Default is `1`

1. **Scope Limit:** v0.4.4 only supports direct factory returns
2. **Simplicity:** Single-level factory detection is well-bounded
3. **Future-proof:** Depth parameter reserved for future multi-hop factories
4. **Low FP Risk:** Direct return detection is reliable
