# H2.8 Scope Specification — Bounded Factory Return Inference

**Feature-ID:** H2.8
**Sprint:** v0.4.4
**Status:** Specification

---

## Ziel

Erweitere H1/H2-Resolution um **Factory Return Inference**: Wenn eine Funktion `ClassName()` zurückgibt, und der Rückgabewert einer Variable oder `self.attr` zugewiesen wird, inferiere den Typ für nachfolgende Methodenaufrufe.

---

## Pattern-Definition

### H2.8 Positive Pattern

```python
# Module-level factory function
def create_client():
    return HTTPClient()

class Example:
    def run(self):
        self.client = create_client()  # H2.8: infer HTTPClient
        self.client.send()             # H2.8: HTTPClient.send resolved
```

### H1 + H2.8 Interaction

```python
def make_service():
    return DataService()

def process():
    svc = make_service()    # H2.8: infer DataService
    svc.process()           # H1 + H2.8: DataService.process resolved
```

### H2 + H2.8 Interaction

```python
def create_handler():
    return RequestHandler()

class API:
    def __init__(self):
        self.handler = create_handler()  # H2.8: infer RequestHandler
    
    def handle(self):
        self.handler.process()  # H2 + H2.8: RequestHandler.process resolved
```

## In Scope

| Pattern | Status |
|---------|--------|
| Module-level factory function returning `ClassName()` | ✅ IN |
| Factory assigned to local var (`x = factory()`) | ✅ IN |
| Factory assigned to self.attr (`self.x = factory()`) | ✅ IN |
| Factory in helper chain (H2.6/H2.7 + H2.8) | ✅ IN |
| Direct `return ClassName()` only | ✅ IN |
| Single-level factory (no nested factory calls) | ✅ IN |
| Conservative on multiple return paths | ✅ IN |

## Out of Scope

| Pattern | Status | Reason |
|---------|--------|--------|
| Conditional returns (if/else) | ❌ OUT | Requires path-sensitive analysis |
| Factory calling another factory | ❌ OUT | Requires multi-hop factory resolution |
| Factory returning `SomeClass.method()` | ❌ OUT | Not a constructor |
| Factory returning variable | ❌ OUT | Requires dataflow analysis |
| Classmethod factories | ❌ OUT | Scope limit (future H2.9) |
| Cross-module factory resolution | ❌ OUT | Requires whole-program analysis |

## Resolution Priority Order

1. **H2.5 method-local** (intra-method assignment)
2. **H2.7 transitive propagated** (from multi-hop helper chain)
3. **H2.6 single-hop propagated** (from direct helper)
4. **H2.8 factory-inferred** (from factory return)
5. **H2 class-level** (`__init__` assignment)
6. **H1 local-var** (local var assignment)

### Why H2.8 > H2

Factory-inferred types are more specific than generic `__init__` assignments:

```python
def create_client():
    return HTTPClient()

class Example:
    def __init__(self):
        self.client = None  # No type from __init__
    
    def setup(self):
        self.client = create_client()  # H2.8: HTTPClient
    
    def run(self):
        self.setup()
        self.client.send()  # H2.8: HTTPClient.send (not from __init__)
```

## Factory Detection

### Valid Factory Pattern

```python
def factory_name():
    return ClassName()       # ✅ Valid: direct constructor return
```

### Invalid Factory Patterns

```python
def factory_a():
    if condition:
        return ClassA()
    return ClassB()          # ❌ Multiple return types

def factory_b():
    x = ClassName()
    return x                 # ❌ Indirect return (variable)

def factory_c():
    return get_instance()    # ❌ Returns function call, not constructor

@classmethod
def factory_d(cls):
    return cls()             # ❌ Classmethod factory (out of scope)
```

## Bounded Propagation

### Factory Call Depth

| Depth | Meaning |
|-------|---------|
| 0 | No factory inference (disabled) |
| 1 | Direct factory call only (default) |
| 2+ | Reserved for future multi-hop factory chains |

### Current Scope

H2.8 v0.4.4 only supports **depth=1** (direct factory call). Multi-hop factory chains (factory calling factory) are out of scope.

---

## Conflict Resolution

### Problem

```python
def create_http():
    return HTTPClient()

def create_ws():
    return WebSocketClient()

class Example:
    def run(self):
        if condition:
            self.client = create_http()
        else:
            self.client = create_ws()
        self.client.send()  # HTTPClient or WebSocketClient?
```

### Solution

Same `self.attr` from different factories with **different types** → `None` (unresolved)

When H2.8 conflicts with H2/H2.5/H2.6/H2.7:
- If same type: use that type
- If different types: unresolved (conservative)

## Algorithm Design

### Phase 1: Factory Index Building

```python
def _build_factory_return_types(
    tree: ast.Module,
    local_classes: dict[str, ClassInfo],
    local_imports: dict[str, str],
    all_classes: dict[str, ClassInfo],
) -> dict[str, str]:
    """
    Build mapping of function names to their return class types.
    
    Only includes functions with a single, direct `return ClassName()` pattern.
    
    Returns: {function_name: class_qname}
    """
```

### Phase 2: Enhanced Type Inference

Modify `_infer_class_from_expr()` to check factory return types:

```python
def _infer_class_from_expr(
    expr: ast.expr,
    local_classes: dict[str, ClassInfo],
    local_imports: dict[str, str],
    all_classes: dict[str, ClassInfo],
    factory_return_types: dict[str, str],  # NEW: H2.8
) -> str | None:
    """H1 + H2.8: Infer class qname from an expression."""
    if isinstance(expr, ast.Call):
        # H1: Direct constructor
        if isinstance(expr.func, ast.Name):
            class_name = expr.func.id
            if class_name in local_classes:
                return local_classes[class_name].qname
            if class_name in local_imports:
                qualified = local_imports[class_name]
                if qualified in all_classes:
                    return qualified
            
            # H2.8: Factory function
            if class_name in factory_return_types:
                return factory_return_types[class_name]
    
    return None
```
