# H2.7 Flag Contract — Feature Flag Design

**Feature-ID:** H2.7
**Sprint:** v0.4.3
**Status:** Contract Definition

---

## Flag Overview

| Flag | Type | Default | ENV Variable |
|------|------|---------|--------------|
| `--enable-h27-self-attr-transitive` | bool | `false` | `CAS_ENABLE_H27_SELF_ATTR_TRANSITIVE` |
| `--h27-max-chain-depth` | int | `2` | `CAS_H27_MAX_CHAIN_DEPTH` |

---

## Primary Flag: `--enable-h27-self-attr-transitive`

### Purpose

Enable/disable H2.7 multi-hop transitive self-attr propagation.

### Values

| Value | Behavior |
|-------|----------|
| `false` (default) | H2.7 disabled, use H2.5/H2.6 only |
| `true` | H2.7 enabled with default depth (2) |

### CLI Usage

```bash
# Enable H2.7
python3 extract_python.py \
  --enable-h27-self-attr-transitive true \
  --repo-root . \
  --repo-name repo://main \
  --revision git:HEAD \
  --out ./evidence

# Disable H2.7 (explicit)
python3 extract_python.py \
  --enable-h27-self-attr-transitive false \
  --repo-root . \
  --out ./evidence
```

### ENV Usage

```bash
CAS_ENABLE_H27_SELF_ATTR_TRANSITIVE=true python3 extract_python.py ...
```

### Precedence

```
CLI flag > ENV variable > Default (false)
```

### Help Text

```
  --enable-h27-self-attr-transitive ENABLE_H27_SELF_ATTR_TRANSITIVE
                        Enable H2.7: resolve self.attr.method() where self.attr
                        is assigned in a multi-hop helper chain (e.g., run()->prepare()->init()).
                        Propagates types transitively through helper calls within the
                        same class. (default: false, ENV: CAS_ENABLE_H27_SELF_ATTR_TRANSITIVE)
```

---

## Secondary Flag: `--h27-max-chain-depth`

### Purpose

Control maximum helper chain depth for H2.7 propagation.

### Values

| Value | Behavior |
|-------|----------|
| `0` | H2.7 effectively disabled (no propagation) |
| `1` | Single-hop only (equivalent to H2.6) |
| `2` (default) | Two-hop chains (caller → helper → sub-helper) |
| `3+` | Deeper chains (higher FP risk) |

### CLI Usage

```bash
# Depth 1 (conservative, same as H2.6)
python3 extract_python.py \
  --enable-h27-self-attr-transitive true \
  --h27-max-chain-depth 1 \
  --repo-root . \
  --out ./evidence

# Depth 3 (aggressive)
python3 extract_python.py \
  --enable-h27-self-attr-transitive true \
  --h27-max-chain-depth 3 \
  --repo-root . \
  --out ./evidence
```

### Help Text

```
  --h27-max-chain-depth H27_MAX_CHAIN_DEPTH
                        Maximum helper chain depth for H2.7 transitive analysis.
                        Depth 1 = single-hop (H2.6 equivalent), Depth 2 = two-hop chain.
                        Higher values may increase coverage but also FP risk.
                        Only effective when --enable-h27-self-attr-transitive is true.
                        (default: 2, ENV: CAS_H27_MAX_CHAIN_DEPTH)
```

## Interaction with Existing Flags

### H2.5 and H2.6 Flags

| H2.5 | H2.6 | H2.7 | Resolution Order |
|------|------|------|------------------|
| OFF | OFF | OFF | H2 only |
| ON | OFF | OFF | H2.5 > H2 |
| OFF | ON | OFF | H2.6 > H2 |
| ON | ON | OFF | H2.5 > H2.6 > H2 |
| OFF | OFF | ON | H2.7 > H2 |
| ON | OFF | ON | H2.5 > H2.7 > H2 |
| ON | ON | ON | H2.5 > H2.7 > H2 |

**Note:** When H2.7 is ON, it supersedes H2.6 (H2.7 is a superset).

### `--emit-unresolved-self-attr`

H2.7 respects this flag for **unresolved** cases.

---

## Default Behavior Rationale

### Why H2.7 Default is `false`

1. **Safety First:** H2.7 introduces deeper analysis with potential for false positives in edge cases
2. **Backward Compatibility:** v0.4.3 produces identical results to v0.4.2 by default
3. **Explicit Opt-In:** Users consciously enable multi-hop propagation
4. **Audit-Friendly:** Conservative defaults reduce audit noise

### Why Depth Default is `2`

1. **Common Pattern:** Most helper chains are 1-2 levels deep
2. **Balance:** Covers common cases without excessive FP risk
3. **Performance:** Deeper chains have higher computational cost
4. **Empirical:** Based on codebase analysis patterns
