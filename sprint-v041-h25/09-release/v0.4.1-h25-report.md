## B) Feature Description

### H2.5: Intra-Method Non-`__init__` Self-Attr Resolution

**Problem:** Prior to v0.4.1, `self.attr.method()` calls were only resolved if `self.attr` was assigned in `__init__`. Assignments in other methods remained unresolved.

**Solution:** H2.5 tracks `self.attr = ClassName()` assignments within the same method body and uses them for dispatch resolution.

### Scope

| IN Scope | OUT of Scope |
|----------|--------------|
| ✅ Intra-Method (write-before-use in same method) | ❌ Cross-Method Propagation |
| ✅ `Assign` + `AnnAssign` | ❌ Factory Return Inference |
| ✅ Last-assignment-wins (within method) | ❌ CFG/Branch-Merge/Path-Sensitivity |
| ✅ Conservative resolution only | ❌ Interprocedural State Analysis |

### Priority Rules

1. **H2.5 method-local** > **H2 class-level (__init__)**
2. **Last assignment wins** within method scope

### Example

```python
class Example:
    def __init__(self):
        self.client = HTTPClient()  # H2 anchor
    
    def reconnect(self):
        self.client = WebSocketClient()  # H2.5 anchor (overrides H2)
        self.client.send()  # Resolves to WebSocketClient.send (H2.5 wins)
    
    def run(self):
        self.client.send()  # Resolves to HTTPClient.send (H2, no H2.5 in run)
```

## G) Usage Guide

### Enable H2.5 (CLI)

```bash
python extract_python.py \
  --repo-root /path/to/repo \
  --repo-name repo://myrepo \
  --revision git:HEAD \
  --enable-h25-self-attr-noninit true \
  --out ./evidence/
```

### Enable H2.5 (ENV)

```bash
export CAS_ENABLE_H25_SELF_ATTR_NONINIT=true
python extract_python.py \
  --repo-root /path/to/repo \
  --repo-name repo://myrepo \
  --revision git:HEAD \
  --out ./evidence/
```

### Disable H2.5 (Default)

```bash
python extract_python.py \
  --repo-root /path/to/repo \
  --repo-name repo://myrepo \
  --revision git:HEAD \
  --out ./evidence/
# H2.5 is OFF by default
```

## H) Recommendations

### Production Use

| Scenario | Recommended Mode |
|----------|-----------------|
| Production analysis | H2.5 OFF (default) |
| Maximum coverage | H2.5 ON |
| Historical comparison | H2.5 OFF |
| CI/CD gates | H2.5 OFF |

### When to Enable H2.5

- Codebases with significant setup/initialization in non-`__init__` methods
- Need for maximum call graph coverage
- Understanding of H2.5 scope limitations

### When to Keep H2.5 OFF

- Production analysis requiring conservative results
- Historical comparison with v0.4.0
- CI/CD gates where stability is critical

## I) Known Limitations

| Limitation | Impact |
|------------|--------|
| Cross-method propagation | Assignments in one method don't affect calls in another |
| Factory inference | `self.attr = factory()` remains unresolved |
| Conditional handling | Conditional assignments not tracked |
| CFG sensitivity | No path-sensitive analysis |
